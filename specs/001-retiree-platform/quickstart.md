# Проверка готовности пилота

Это сценарии будущей проверки, не отчёт о выполненных испытаниях. Приложение не создано, команд запуска приложения нет.

## Подготовка
Назначить координатора и проверяющего; подготовить закрытый реестр по data-model.md; создать только вымышленных участников, исполнителей и пакет. Один исполнитель active, второй pending, один пакет с достаточным остатком, другой исчерпан. Согласовать правила отмены и часы работы. Для реальных людей дополнительно нужны финансирование, утверждённые условия и работающий канал поддержки.

## Сценарии

| Проверка | Действие | Ожидаемый результат |
| --- | --- | --- |
| Основной путь, FR-001/002/004/006 | Принять обращение по телефону, согласовать условия 0, назначить, подтвердить выполнение | Один id, история статусов, согласие, подтверждённый результат |
| Проверка исполнителя, FR-003 | Попытаться назначить pending, затем suspended | Оба назначения запрещены |
| Лимит, FR-005 | При остатке 100 условных единиц зарезервировать 70, затем попытаться 40 | Второй резерв запрещён; после отмены 70 доступно снова 100 |
| Учёт, FR-005/010 | Резерв 70 перевести в расход 70 при поступлении 100 | Остаток 30, а не −40; резерв обнулён |
| Дубликат, FR-001 | Повторно передать ту же заявку | Новое обязательство и второй id случая не создаются |
| Нет подтверждения, FR-006 | Исполнитель завершил, получатель не ответил | pending_confirmation, в подтверждённый эффект не включено |
| Жалоба, FR-007 | Зарегистрировать риск и приостановить исполнителя | Ответственный назначен; новые заказы заблокированы |
| Согласие, FR-008 | Родственник без согласия запрашивает адрес; затем согласие отозвано | Доступ не предоставляется в обоих случаях |
| Встреча, FR-009 | Заполнить лимит мест, добавить ещё одного, отменить встречу | Лист ожидания; уведомления записанным; явка не засчитана |
| Отчёт, FR-010 | Один человек получил две услуги и посетил встречу | 1 уникальный получатель, 2 случая, 1 посещение; нет раскрытия контактов |

## Проба с пользователями
После проверки макета провести 5 решенческих проб. Плановый порог: минимум 4 участника понимают условия и могут запросить помощь выбранным способом без пошаговых подсказок. Отдельно фиксировать языковые и цифровые затруднения; поправить форму и инструкцию.

## Реальный пилот
Только после подготовки выполнить календарь STARTUP-PLAN.md. Сравнить результаты с SC-001–007 и записать числа, знаменатели и ограничения. Не отмечать спрос или социальный эффект подтверждённым по синтетическим сценариям.
