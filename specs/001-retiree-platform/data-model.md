# Модель данных ручного пилота

Таблицы - логические сущности, не выбранная база данных. Тестирование подготовки только на вымышленных записях.

| Сущность | Минимальные поля | Связи и ограничения |
| --- | --- | --- |
| Participant | id, имя для обращения, контакт, язык, район, потребность, согласие, дата | Один id на человека; адрес в закрытой записи только для заказа |
| Consent | id, participant_id, цель, получатель доступа, дата, отзыв | Согласие родственнику отдельно от согласия на услугу; отозванное не действует |
| Provider | id, контакт, услуга, зона, доступность, статус | Назначается только при статусе active |
| Verification | provider_id, тип проверки, дата, проверяющий, результат, пересмотр | Отсутствие любого обязательного пункта запрещает active; не хранить избыточные копии документов |
| Partner | id, организация, деловой контакт, согласованные условия | Отделён от пользователя; не получает адреса |
| FundingPackage | id, partner_id, срок, оплаченная сумма, лимит случаев, ограничения расходов | Только полученные средства доступны; натуральная поддержка отдельной строкой |
| Request | id, participant_id, услуга, условия, цена участника, provider_id, package_id, дата, статус | Бесплатный базовый заказ: цена 0; не дублировать один случай |
| LedgerEntry | id, package_id, request_id, тип, сумма, время, подтверждение | Типы: поступление, резерв, снятие резерва, расход, возврат; резерв не равен расходу |
| Event | id, организатор, место, время, вместимость, цена, статус | Цена базового события 0; отмена уведомляет участников |
| Attendance | event_id, participant_id, запись, явка | Уникальная пара; запись не равна посещению |
| Incident | id, request_id или event_id, описание, ответственный, статус, решение | Доступ только ответственным; серьёзный риск приостанавливает назначения |
| Outcome | participant_id, request_id или event_id, дата, исходное состояние, результат, ответ получен | Отсутствие ответа не равно положительному результату |
| TimeCost | случай или период, роль, минуты, денежная выплата, оценка замены | Волонтёрская оценка и фактическая выплата не складываются дважды |

## Переходы состояний

Заявка: received → assessed → consented → funded → scheduled → completed_pending_confirmation → confirmed. Отмена возможна до выполнения с причиной; жалоба связывается с заявкой независимо от статуса выполнения. Исполнитель: pending → active → suspended → active либо rejected после пересмотра. Финансирование: proposed → agreed → paid → allocated → reported → closed; частичный платёж разрешает обязательства только в полученном объёме.

## Денежные инварианты
Доступный остаток = поступления − фактические расходы − активные резервы − возвраты. Подтверждённый расход одновременно снимает соответствующий резерв. Отмена снимает резерв; реальная невозвратная стоимость отмены учитывается отдельно. Новый заказ нельзя назначить при отрицательном прогнозном остатке или исчерпанном лимите случаев. В ручном пилоте запись резервов ведёт один ответственный, чтобы исключить одновременное двойное расходование.

## Доступ
Координатор видит контакты и заявки; назначенный исполнитель - только необходимые сведения конкретного визита; аналитик - псевдонимизированные записи; партнёр - агрегаты. Права родственника привязаны к Consent. Сроки хранения, место размещения и процедура удаления определяются оператором до реального сбора. До этого реестр содержит только синтетические данные.
