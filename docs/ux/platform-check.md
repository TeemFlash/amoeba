# Проверка требований Android и iPhone

Проверено основным агентом 2026-11-09. Это нормативный контекст для задач Astra, не результаты тестирования приложения.

## Размеры и текст

Android рекомендует область касания не менее 48×48 dp; визуальная иконка может быть меньше при достаточной активной области. Текст и подписи должны поддерживать масштабирование. Источник: [Android Developers](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views?hl=en).

Текущая таблица Apple HIG указывает для iOS стандартный размер элемента управления 44×44 pt и минимальный 28×28 pt. Для этого приложения не стоит проектировать по наименьшему допустимому значению: более крупная цель задаётся отдельно как проектное решение. Apple также рекомендует возможность увеличивать текст минимум на 200%, в том числе через Dynamic Type. Проверен официальный Markdown страницы, поскольку web-инструмент не смог отобразить его тип содержимого: [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/accessibility), [официальный Markdown](https://developer.apple.com/design/human-interface-guidelines/accessibility.md).

Размеры Android dp/sp, iOS pt и web CSS px нельзя обозначать одной общей единицей px. WCAG 2.2 AA 2.5.8 задаёт 24×24 CSS px с исключениями, а enhanced 2.5.5 - 44×44 CSS px. Это не основание ставить 24 dp кнопки в приложении пенсионеров. [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Критерии проверки макета и реализации

- Поддержка системного размера шрифта проверяется отдельно на Android и iOS, включая максимальные доступные размеры; содержимое доступно через прокрутку, элементы не перекрываются.
- Текстовые подписи и доступные названия обозначают действие, а не только форму иконки. TalkBack и VoiceOver объявляют роль, состояние и результат.
- Для основных действий есть видимая кнопка; свайп, длительное нажатие и перетаскивание не являются единственным способом.
- Навигация назад сохраняет смысл сценария и введённые сведения, если пользователь явно не выбрал удаление черновика.
- Ошибка сети не обозначается как успех; повторная попытка не создаёт дубликат заявки или записи на встречу.
- Просмотр доступного содержания не требует предоставления контактов, геолокации, микрофона или уведомлений.
- Разрешение запрашивается в контексте конкретного действия; отказ оставляет доступный альтернативный путь там, где он возможен.
- Не обещать живого оператора или экстренную помощь без соответствующей действующей службы. В демонстрации такие действия явно помечаются.

## Вход

Вход проектируется после проверки необходимости личного действия, а не как обязательный первый экран. При выборе кодов или паролей разрешены вставка и системное автозаполнение; предусмотрены неверный код, истечение, отсутствие доставки и восстановление. Биометрия не является единственным путём. Принцип снижения нагрузки на память поддерживается [W3C Accessible Authentication](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html); конкретные механизмы и безопасное хранение требуют отдельного технического решения.
