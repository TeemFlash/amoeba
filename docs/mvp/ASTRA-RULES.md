# Правила локального MVP — Astra

> Последнее уточнение интерфейса: [выбор города и макет входа](CITY-AND-SIGN-IN.md). По запросу пользователя постоянная demo-плашка и i удаляются; форма авторизации пока только макет. Остальные локальные ограничения действуют.

Дата: 2026-11-09. Статус: исполнимое решение Astra для реализации Luna по текущему поручению пользователя. Это следующий узкий этап после исследования и UX-документов, а не заявление о запуске сервиса. Исходные материалы: [приоритеты](../ux/astra-priorities.md), [исследование](../ux/luna-research.md), [спецификация 002](../../specs/002-senior-mobile-ux/spec.md).

## 1. Результат и границы

Работающее локальное демо с исходниками приложения Android/iOS и проверяемым web preview: бытовая помощь → условия → выбор района и времени → проверка → локальная запись → мои обращения → отмена. Второй путь: встречи → условия → проверка → локальная запись → отмена. RU/KZ, восстановление данных после перезапуска и крупные доступные элементы входят в оба пути.

На каждом экране видна плашка: **«Демо. Услуги не заказываются, встречи не проводятся.»** / **«Демо. Қызметтерге тапсырыс берілмейді, кездесулер өткізілмейді.»** Все названия, предложения, места и даты — учебные примеры. В условиях: «Стоимость не определена. В демо оплаты нет»; не подставлять «бесплатно». Фиктивные места помечать «Демонстрационное место — не адрес для посещения». Не использовать настоящих людей, телефоны, почту, точные адреса, отзывы, оценки, значки проверки или организационные обещания.

Нет регистрации, аккаунтов, оператора, backend, запросов API, платежей, геолокации, уведомлений, семейных ролей, жалоб с номером, списка ожидания, назначения исполнителей, реальной отправки или обещания ответа. В «Об приложении» есть инструкция и явное отсутствие поддержки. Бюджет и монетизация не входят в работу. Сетевые статусы из 002, потерянный серверный ответ и серверная защита от дублей остаются будущими требованиями: их нельзя выдавать за реализованные в локальном приложении.

## 2. Инженерное решение и альтернативы

**TypeScript + React Native + Expo**, локальный AsyncStorage; React Native Web используется для проверяемого preview на этом Linux-хосте. React state/context и небольшой собственный стек экранов достаточны; Redux, сервер, ORM и авторизация не нужны. Установленные версии закрепляются lockfile, совместимые пакеты Expo ставятся через `expo install`; номер SDK не угадывать и не брать prerelease автоматически.

| Вариант | Для этого MVP | Решение |
| --- | --- | --- |
| React Native + Expo + TypeScript | Общий исходный проект Android/iOS/web; доступны Node/npm; TypeScript задаёт проверяемые контракты состояний | Выбран Astra для текущей реализации |
| Flutter + Dart | Также общий мобильный/web проект; пригоден для будущего продукта, но требует установки отдельного SDK; Dart здесь не даёт преимущества, оправдывающего смену окружения | Допустимая альтернатива, сейчас не выбран |
| Kotlin + Jetpack Compose и Swift + SwiftUI | Отдельные нативные приложения, два UI и два набора проверок; разумны при специальных платформенных требованиях | Избыточно для одного небольшого демо |

Официальные основания, проверены 2026-11-09: [Expo: универсальный проект](https://docs.expo.dev/tutorial/create-your-first-app/), [Expo: TypeScript](https://docs.expo.dev/guides/typescript/), [Expo: хранение](https://docs.expo.dev/develop/user-interface/store-data/), [Flutter: платформы и iOS на macOS](https://docs.flutter.dev/platform-integration), [Android: Compose](https://developer.android.com/develop/ui/compose), [Apple: SwiftUI](https://developer.apple.com/swiftui/), [React Native: accessibility](https://reactnative.dev/docs/accessibility).

Это инженерный выбор Astra, не приписываем его пользователю как уже высказанное предпочтение. Web-проверка не подтверждает Android/iOS, TalkBack/VoiceOver или пригодность для пожилых жителей Астаны. Сборка iOS, подпись и публикация требуют отдельного доступного Apple toolchain/окружения. Ничего не публикуем.

## 3. Данные и контракты

Все ID стабильны и не переводятся. Даты сохранения — ISO UTC. Предложения времени и встречи — **фиксированные демонстрационные примеры**, без утверждения будущего реального расписания; календарная актуальность не вычисляется. Выбор только из закрытых списков: свободных полей нет, реальные персональные данные не собираются.

```ts
type Locale = 'ru' | 'kz'; // пользовательская метка KZ; Intl использует kk-KZ
type Localized = Record<Locale, string>;
type ServiceId = 'groceries' | 'home-help' | 'digital-help';
type DistrictId = 'demo-center' | 'demo-left-bank';
type SlotId = 'demo-morning' | 'demo-afternoon';
type EventId = 'tea' | 'walk-full' | 'club-cancelled';
type EventAvailability = 'open' | 'full' | 'cancelled';
type EntryStatus = 'saved-demo' | 'cancelled-demo';

interface Service {
  id: ServiceId;
  title: Localized;
  description: Localized;
  includes: Localized;
  excludes: Localized;
}
interface DemoEvent {
  id: EventId;
  title: Localized;
  description: Localized;
  dateLabel: Localized;
  place: Localized;
  languages: Localized;
  accessibility: Localized; // честно: сведения о доступности не проверены
  availability: EventAvailability;
}
interface HelpDraft {
  operationId: string; // создаётся однажды при начале нового черновика
  serviceId: ServiceId;
  districtId: DistrictId | null;
  slotId: SlotId | null;
  step: 'form' | 'review';
}
interface EntryBase {
  id: string; // DEMO- + operationId; не номер реальной заявки
  operationId: string;
  status: EntryStatus;
  createdAt: string;
  cancelledAt: string | null;
}
type Entry =
  | (EntryBase & { kind: 'help'; serviceId: ServiceId;
      districtId: DistrictId; slotId: SlotId })
  | (EntryBase & { kind: 'event'; eventId: EventId });
interface AppState {
  schemaVersion: 1;
  locale: Locale;
  draft: HelpDraft | null;
  entries: Entry[];
}
```

Каталог `catalog.ts` содержит три услуги и три встречи: одна доступна в демо, одна полная, одна отменена. Никаких случайных статусов или задержек, изображающих работу людей. Встреча не требует заявки на помощь. Информация об исполнителе/организаторе: «Реальный исполнитель/организатор не назначен; сведения о проверке отсутствуют» в соответствующем контексте.

## 4. Переходы и точная семантика

```text
нет черновика → form → review → saved-demo → cancelled-demo
                   ↑       |
                   └ изменить

встреча open → проверка → saved-demo → cancelled-demo
встреча full/cancelled → только просмотр причины и возврат
```

- `saved-demo`: **«Сохранено в демо»**, «Запись хранится только на этом устройстве. Никому не отправлена». В визите никто не согласован, место на реальной встрече не занято.
- `cancelled-demo`: **«Отменено в демо»**, запись остаётся в истории. Отмена разрешена только после отдельного экрана подтверждения с кнопками «Оставить» и «Отменить в демо».
- Повтор отмены того же ID успешен без изменения первоначального `cancelledAt`.
- Повтор `submitHelp` или `enrollEvent` с прежним `operationId` возвращает исходную запись, включая отменённую; не восстанавливает её.
- Для одной встречи допускается не более одной активной локальной записи. Новая попытка с другим `operationId`, пока активная запись существует, возвращает `ALREADY_ENROLLED` с её `existingEntryId`; UI предлагает открыть эту запись. После отмены можно начать новую запись с новым ID.
- Не допускается «редактирование отправленной заявки»: до сохранения есть «Изменить»; после — отменить и начать новый пример. Это сознательное ограничение данного среза.
- Переход назад, смена языка и переключение разделов не очищают черновик. На главной есть «Продолжить черновик». Новый черновик другой услуги при существующем требует явного подтверждения замены. Отдельное удаление черновика также подтверждается.
- Во время локальной записи кнопка disabled и подписана «Сохраняем…». Успех показывается только после завершения `storage.setItem`. Защита от дубля основана также на ID и последовательной очереди команд, а не только disabled-кнопке.

Ошибки возвращаются типизированно, технический код не показывается вместо человеческого текста. Все тексты имеют RU/KZ.

| Код | Условие | Поведение |
| --- | --- | --- |
| `DRAFT_EXISTS` | Начало нового черновика при существующем без `replace: true` | Продолжить существующий или подтвердить замену |
| `DRAFT_NOT_FOUND` | Изменение/отправка отсутствующего черновика, если operationId не найден среди записей | Вернуться к каталогу |
| `INVALID_SELECTION` | Неизвестный ID/значение enum; нельзя записать произвольные поля | Сообщение «Выберите вариант из списка», ничего не изменять |
| `DISTRICT_REQUIRED` | Отправка/переход к review без района | Ошибка рядом с выбором района |
| `SLOT_REQUIRED` | Район есть, время отсутствует | Ошибка рядом с выбором времени |
| `EVENT_FULL` | Запись на полную встречу | Показать причину, оставить просмотр |
| `EVENT_CANCELLED` | Запись на отменённую встречу | Показать причину, оставить просмотр |
| `ALREADY_ENROLLED` | Есть активная запись на эту встречу | Открыть её по `existingEntryId` |
| `ENTRY_NOT_FOUND` | Неизвестный ID обращения для отмены | Объяснить, перейти в список |
| `STORAGE_READ_FAILED` | Чтение локального хранилища завершилось исключением | Блокировать изменения, «Повторить» |
| `STORAGE_CORRUPT` | JSON, версия, структура, значения или ссылки невалидны | Не затирать данные; повтор чтения либо подтверждённый сброс демо |
| `STORAGE_WRITE_FAILED` | Запись не подтверждена | «Не удалось подтвердить сохранение. Повторите попытку»; успех не показывать; ввод и operationId сохранить |

Порядок проверки отправки помощи: сначала найти прежний `operationId`, затем существование и соответствие черновика, корректность ID, район, время. Если `operationId` не совпадает с текущим черновиком и не найден в истории — `INVALID_SELECTION`. У встречи: прежний `operationId`, валидный eventId, существующая активная запись, доступность. Повторный ID с другим видом/каталоговым объектом — `INVALID_SELECTION`, а не успешный ответ на другое намерение. Нельзя создать пустую запись из состояния UI.

## 5. Хранение и восстановление

Единый ключ `enactus-senior-demo:v1`, JSON `AppState` через AsyncStorage. Он **не зашифрован**, поэтому хранит только синтетический выбор, локальные ID, статусы, время и язык. Никаких токенов или ПДн. В браузере данные относятся к данному origin/профилю; удаление данных браузера или приложения удалит демо.

Первое чтение — обязательный gate: до него показана загрузка, запись запрещена. `null` означает чистое начальное состояние RU, без черновика и обращений. Невалидное содержимое — ошибка, не молчаливый reset. Валидатор проверяет вложенные структуры, enum, уникальные ID/operationId, обязательные поля, согласованность статуса и `cancelledAt`, максимум одну активную запись на встречу. Неизвестные поля не переносить в нормализованное состояние.

Сохранение идёт одной последовательной очередью: считать последний успешно принятый state → применить команду → записать целый новый snapshot → только затем обновить state/UI. Ошибка не ломает очередь следующих попыток. Не писать в useEffect автоматически начальное состояние поверх загружаемого. При неудаче записи UI сохраняет несохранённый ввод отдельно и тот же operationId для повтора; нельзя заявлять, что запись точно не состоялась. Повтор не добавляет вторую запись. После перезапуска читать фактическое хранилище заново.

Поддерживается один активный экземпляр демо. Между вкладками/устройствами синхронизации и транзакций нет; не заявлять многопользовательскую защиту. Сброс в «Об приложении» требует подтверждения, удаляет только данный ключ и очищает состояние лишь после успешного завершения. Отдельный reset не использовать как молчаливое восстановление после ошибок.

## 6. Навигация и визуальная система

Постоянные разделы: **Главная / Басты бет**, **Мои обращения / Менің өтініштерім**, **Об приложении / Қолданба туралы**. На главной две выразительные крупные карточки «Бытовая помощь» и «Встречи», затем продолжение черновика. Верх: название «Помощь рядом» / «Жақыннан көмек», Астана, выбор RU/KZ. Во вложенном экране видимая «Назад»; Android Back использует тот же стек. Верхний Back никогда не отправляет и не отменяет данные. При возврате из итогового статуса открывать «Мои обращения», а не прежнюю кнопку отправки.

Фон `#F7F6F0`, белые карточки, основной текст `#172B24`, вторичный `#45574E`, основной зелёный `#245A43`, ошибка `#A12B24`, тонкая граница `#C8D3CC`. Белый текст допускается на зелёном; контраст измерить. Отступы 8/12/16/24/32, карточки radius 20, кнопки radius 14. Body 18, заголовок 28; обычная ширина контента до 760, без тяжёлой desktop-сетки. Кнопки minHeight 56 с padding; высота не фиксируется, длинный текст переносится. Иконки только дополнительны; без emoji вместо подписи и без внешних изображений/шрифтов/аналитики.

Все экраны прокручиваются, safe area учитывается. Поддерживать font scaling, не ограничивать `maxFontSizeMultiplier`; элементы меню переносятся при крупном тексте. Нижняя навигация не перекрывает прокручиваемое содержимое, последняя кнопка доступна целиком. Роль и доступное имя есть у каждой кнопки; выбранность, disabled и ошибки доступны диктору; ошибка/успех объявляются через accessibility API. Порядок чтения совпадает с визуальным, заголовки имеют роль header, важные статусы текстовые. На web виден клавиатурный focus. Не утверждать прохождение TalkBack/VoiceOver без реального прогона.

Строки интерфейса, условий, ошибок и подтверждений — в едином типизированном словаре `i18n.ts`; второй язык обязан иметь тот же набор ключей. Для Intl использовать `ru-KZ` и `kk-KZ`, а не `kz`. Смена языка не изменяет ID/данные/экран. Казахский перевод — рабочий, требует редакторской проверки носителем перед реальным использованием; это указать в README/проверке, а не выдавать за пользовательское исследование.

## 7. Критерии приёмки данного среза

1. Чистый запуск показывает две задачи, честную demo-плашку и пустую историю. Просмотр не требует разрешений и входа.
2. Услуга → выбор двух значений → проверка → изменение → сохранение → история → подтверждённая отмена работают; запись после перезапуска сохраняется.
3. Пустой район/время не создаёт обращения; быстрый повтор одного operationId создаёт ровно одну запись. Неудачная запись хранилища не показывает успех.
4. Черновик переживает Back, разделы и перезапуск; язык переключается на review без сброса выбранного.
5. Доступная встреча записывается независимо от помощи; полная/отменённая блокируются доменной логикой и UI. Повторная активная запись не создаётся; после отмены можно начать новую.
6. Все доменные ошибки, отмена, пустые экраны, данные карточек и инструкция доступны на обоих языках. ID и история от языка не меняются.
7. Повреждённое хранилище не перезаписывается молча; повтор чтения и подтверждённый reset доступны. Сбой записи покрыт инъекцией fake storage в тестах.
8. Проверяемый web preview при ширине 320px и 390px, затем при 200% масштабе не обрезает основные действия и длинный RU/KZ текст; кнопки доступны клавиатурой, контраст измерен. Результаты записать фактически.
9. Нет прикладных сетевых запросов/внешних assets. Web preview требует локальный сервер для загрузки bundle; обещание offline reload/PWA не делается. После загрузки сценарии не обращаются к backend.
10. Typecheck, доменные/хранилищные тесты и web export проходят. Отдельно перечислены непроведённые Android/iOS, дикторные и пользовательские проверки. Запуск preview не называется публикацией продукта.
