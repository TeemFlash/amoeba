### U7 / P1 — недоступность сценария при крупном тексте

Основной агент воспроизвёл в браузере на KZ, ширине 320px и эмуляции текста ×2 (`fontSize`/`lineHeight`): фиксированные header и demo-banner занимают около 725 из 844px высоты, форме почти не остаётся видимой области; подписи нижней навигации перекрываются; длинный radio-текст выходит за доступную ширину (362 против 286px), ширина документа становится 335 вместо 320px. Обычные 320px без увеличения прошли. Артефакт проверки: `work/mvp-qa/kz-form-320-text-2x.png`, сценарий `layout_mvp.py` у основного агента.

Место: компоновка `App.tsx` (непрокручиваемые header/notice и tab bar вокруг flex-области содержимого), переносы `src/ui/components.tsx` и подписи tabs. Необходимое исправление: общий доступный scroll для крупного header и содержимого, перенос/адаптация нижней навигации и длинных слов без обрезки действий. Это существующий критерий приёмки ASTRA-RULES, не расширение scope. U7 блокирует итоговую UX-приёмку до повторного browser-прогона. Эмуляция текста в web не считается испытанием системного масштаба Android/iOS.

Дополнение U6 из browser QA основного агента: выбор radio сохраняется и визуально восстанавливается после reload, но в DOM отсутствует `aria-checked` при наличии `role="radio"`. Следовательно, одного `accessibilityState.checked` в этой версии RN Web недостаточно. Luna передана необходимость явного web aria alias при сохранении native state. Итоговая проверка семантики остаётся обязательной даже если функциональный smoke продолжен без этого конкретного assertion.
