# Выбор города и макет входа

## Актуальное уточнение пользователя

Этот этап заменяет прежние требования о постоянной demo-плашке и запрете экрана аккаунта. Убрать из шапки «Демо · ничего не отправляется» и кнопку i. Вместо статичного города добавить выбор с поиском, крупными строками и сохранением на устройстве. Экран About и сброс данных остаются доступны по текстовой ссылке.

Последнее решение пользователя: сейчас нужен только макет авторизации; реальное подключение Firebase отложено. Макет показывается первым при запуске. «Продолжить без входа» открывает обычный корень приложения — каталог помощи; вход не дублируется кнопкой в шапке. Пока пользователь находится в стартовом потоке входа/About, вкладки скрыты, About доступен со страницы входа и каталога. Back из About возвращает к входу. На странице входа город в шапке скрыт, переключатель RU/KZ остаётся. Начальная страница обычного приложения по-прежнему `initialRoute` — каталог помощи. Не отправлять и не сохранять почту/пароль. Не показывать успешный вход или созданный аккаунт. Не добавлять фиктивные отзывы, счётчик пользователей и неработающий Google OAuth.

Выбор города является локальным предпочтением: он не создаёт реальных предложений в выбранном городе и не переносит существующие записи. Районы существующего каталога остаются демонстрационными примерами Астаны. Ошибки чтения/записи города видимы; повреждённое значение не затирается молча. Исходный AppState и его ключ не мигрируются.

## Компонент и зависимости

Проект уже использует TypeScript, React Native и Expo. Общие элементы: `apps/mobile/src/ui/components.tsx`; токены: `apps/mobile/src/ui/theme.ts`. Форма: `apps/mobile/components/ui/modern-stunning-sign-in.tsx`, именованный и default export `SignIn1`. Это адаптация присланной карточки на мобильные элементы: видимые подписи, крупные поля, переключение видимости пароля, ошибки RU/KZ и необязательный вход.

`components/ui` создан внутри приложения для отдельного переиспользуемого компонента. Это соглашение об организации, а не техническое требование React или условие доступности. Прямой относительный импорт не требует alias `@/`.

Присланный DOM-компонент с `div`, `input` и Tailwind-классами не рендерится нативно на Android/iPhone. Его разметка адаптирована к `View`, `TextInput` и `Pressable`; дополнительные context providers не нужны. React Native TextInput: https://reactnative.dev/docs/textinput . Иконки берутся из уже установленного react-native-svg; lucide-react и stock-фотографии не нужны для формы входа.

## Если понадобится отдельный web-проект с shadcn

Не выполнять эти команды внутри существующего мобильного приложения. Для отдельного React/TypeScript web-приложения:

```sh
npm create vite@latest web -- --template react-ts
cd web
npm install
npm install tailwindcss @tailwindcss/vite
```

Добавить `tailwindcss()` из `@tailwindcss/vite` в plugins `vite.config.ts`, а в `src/index.css` добавить `@import "tailwindcss";`. Настроить alias `@` на `src` в Vite и TypeScript, затем выполнить `npx shadcn@latest init`. В `components.json` aliases.ui должен указывать на `@/components/ui`; компоненты будут находиться в `src/components/ui`. Это позволяет CLI и импортам указывать в одно место. Перед копированием исходного DOM-компонента заменить fake-success handler реальным клиентом авторизации и подписать поля.

Официальная инструкция: https://ui.shadcn.com/docs/installation/vite . Отдельный web-проект в этом этапе не создавался.

## Будущее подключение Firebase

Firebase выбран пользователем для следующего этапа. Понадобятся публичная web-конфигурация проекта и включённый Email/Password provider. SDK, аккаунты и сетевые запросы не входят в текущий макет. Инструкция: https://firebase.google.com/docs/auth/web/password-auth .
